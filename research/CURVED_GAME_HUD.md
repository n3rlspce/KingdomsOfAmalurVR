# Curved game HUD prototype

User priority: the actual health/mana bars, minimap and action bar should all be
visible in front of the player, curved and farther away. This is separate from
the mod settings panel.

Reuses mikear69's existing HUD shader classifications:
`887f6506d28f9ff1`, `bd9cebc4f7e1ed36`, and minimap `cc7258d9790a0bbd`.
The separately marked menu shader `bf098be2e4587ca5` is unchanged. Shared usage
of the three modified shaders by other UI screens still needs checking.

`tools/build-hud-shaders.ps1` preserves the donor transforms/texture inputs and
replaces only their final HUD position adjustment. IniParams row 2 holds X/Y
clip-space extents (0.38/0.40), half arc (0.60 radians), and empirical stereo
offset (0.10). Vertex positions are projected onto a cylindrical layout, with
clip W preserved to avoid geo-11 applying world-geometry stereo correction. This approximates curvature
on the game's existing triangles; it is not a separately tessellated UI surface.

F6 switches curved/stock layout. F4 cycles HUD stereo offsets 0.10, 0, 0.25, 0.5.
The original donor uses 0.5. Smaller offset is a candidate for a more distant HUD,
not a calibrated physical distance. Eye reversal and bridge alignment affect
perceived depth; the farther-away requirement is not yet verified.

All three generated shaders compiled with fxc vs_4_0 and are installed via the
normal receipt-backed package. The initial capture showed only startup content,
so gameplay HUD coverage, clipping/stencil behavior, minimap alignment, apparent
distance and readability remain unverified. Load gameplay and capture before
claiming success. If any HUD pass is omitted or native scissoring breaks the
curved layout, revert with F6 and isolate those passes before changing more math.

## Menu regression patch (19 September, 18:59)

Installed a draw-based automatic gate using geo-11's existing Preset and
exclude_preset command-list support (behavior checked in upstream 3Dmigoto
Override.cpp). IniParams row 3 X starts at zero. The minimap shader triggers
PresetVRGameplayHud; the separately identified menu shader vetoes it. Presets
expire when not triggered and update at Present, so transitions may lag a frame.
All three curved shader candidates now require this gate as well as the F6
layout switch. F6 cannot force curvature past the gate. Original menu shader
and stock coordinates remain unchanged. This is a rendering heuristic, NOT
verified authoritative engine UI state; shared use of either trigger can cause
false positives or suppress the gameplay HUD. Inventory, pause, dialogue and
loading transitions still need real-scene checks. If the menu shader appears
in normal HUD rendering, narrow its classification before declaring success.

Built the native DLL and compiled all three shaders with fxc vs_4_0 successfully.
Installed through the receipt-backed installer and invalidated nine generated
shader caches. F8 now rearms the read-only HUD diagnostic, including a row-3 gate
readback, allowing menu/gameplay comparison without replacing the DLL again.
Runtime menu and gameplay validation is pending.
